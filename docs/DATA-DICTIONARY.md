# 电量与费用定义

id为计量号、order为订单号、station为站点，均为字符串。kind取order或station。计量start/end必须带时区，区间[start,end)，最大72小时可调至168小时。energy以kWh或MWh输入，输出kWh。未知哨兵不等于零。
费率版本以本地+08日期[from,to)生效；日内时段必须完整无重叠覆盖0–24小时。默认11月17日调整尖峰价，可在API参数tariffs中提供相同结构版本清单。
计量段内假定匀速用电，电量按时长交集分配，最后一段修正Decimal除法尾数保证电量严格守恒。跨日以当地日期重选版本。每段输出带当地日期`day`与费率时段`slot_a/slot_b`及峰平谷`label`。
每站唯一总表电量减订单电量为损耗。损耗按**分时两级**分配：先按`(站点,当地日期,费率时段)`汇总总表分段电量与订单分段电量，时段正损耗按段内电量占比落到该时段订单分段；负损耗（时段订单超过总表）或无订单承接的时段不硬摊，记入`period_rows`时段异常证据，其缺口并入站级残差池；残差池按订单电量占比分到各订单的分段，最后一段强制对齐，使分段损耗、订单份额、总表损耗三处严格守恒。总表缺失、重复、负总损耗或无订单承接时整站标记异常，不强行分配。
订单应收=各分时电量×费率+损耗份额×loss_rate；每个分段同时给出含损单价`gross_rate=费率+分段损耗×loss_rate/分段电量`与未舍入分时费`raw_fee`，同一`(站点,订单,日期,时段)`唯一。先算站总额再最大余额分币，稳定id打破余数并列，保证站点实付等于订单份额之和。JSON金额为Decimal字符串。账单bill为CNY，差额=应收-bill，容差边界包含；时段异常站的订单带`period_flag`提示但不阻断站级结算。
版本最高者采信，同版冲突全部隔离；重复和旧版计入隔离。输入行数=采信+隔离。批次哈希包含输入摘要、规则版本、参数；补读批次额外混入`base_run`，与普通批次及不同来源批次互不撞号。复核乐观锁防止旧提交覆盖。
补读入口`POST /api/reread/<run_id>`：补读数据先完整跑通七阶段才落账；任何计算失败返回422原因码`REREAD`且不新增任何记录，旧版账单原样可查。相同补读内容重试返回同一批次并标记`reread.status=reused`，不新增账单。已复核账单的payload与复核状态永不被补读改写。

站点总表区间必须覆盖其全部订单区间；未覆盖标记总表未覆盖订单区间，损耗不强制分摊，账单结论为待复核。
